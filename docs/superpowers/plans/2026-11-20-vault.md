# VAULT · New Tiers · Save Export Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a second prestige layer (VAULT, ★ currency + VAULT tab), three coin tiers past OMEGA, AUTO CASH, and save-code export/import.

**Architecture:** Everything stays in `index.html`. Pure formulas go in the `/*ECON*/ … /*ENDECON*/` block so `tools/econ.mjs` can load them for node tests and the sim. Game state, UI, and fx extend the existing patterns (SHOP list with `tab`, `cashOut`/`cashFinale` ghost animation, `confirmOpen` modal, `bounceFx`/`update`/`drawCoins` fx switches).

**Tech Stack:** Vanilla JS + canvas, node (`node:assert`) for tests/sim, Playwright for the browser check.

**Spec:** `docs/superpowers/specs/2026-11-20-vault-design.md`

## Global Constraints

- Single `index.html`, zero assets, 180×320 logical canvas, 3×5 bitmap font (5×5 glyphs allowed); account for `EX`.
- No `//` comments inside one-line functions.
- `sw.js` VERSION `bb-5` → `bb-6`.
- Save stays `v:2`; missing new fields default to 0 / `chipsAll = chipsEver`.
- Runs 1–30 of `node tools/sim.mjs` must keep passing every existing check.

## Review Focus

1. A pre-VAULT v2 save (no `stars`/`chipsAll`/new shop keys) loads with progress intact and `chipsAll === chipsEver`.
2. AUTO CASH never fires while the BANK is open or while VAULT is available (would throw away a VAULT the player reached).
3. LOAD with empty/cancelled/garbage input changes nothing and shows `BAD CODE` for garbage.
4. After a successful LOAD, the reload's `pagehide` save must not overwrite the imported save.
5. STAR TIER bought with NEW TIER at 0 still yields a contiguous tier ladder, and NEW TIER/STAR TIER labels name the next locked tier.
