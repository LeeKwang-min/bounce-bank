# Bounce Bank — 성장 요소 확장 설계 (prestige · 패드 레벨 · 속도)

작성일: 2026-11-19 · 대상: `index.html` (단일 파일, 에셋 0개)

## 1. 의도와 이유

idle 게임은 켜두고 보다가 **중간중간 화면이 확 바뀌거나 강해지는 순간**을 보는 맛인데, 현재 Bounce Bank는 그 순간이 적고 일정 스테이지 이후 진행이 막힌다.

현재 구조의 벽 (코드 기준):
- 목표 `goal(s)`는 스테이지당 ×5 (6~8스테이지는 ×7~10), 수익 배율 `mult()`는 ×2.
- 패드 9개 · PRISM 등급 · 코인 30개를 채우면 성장 수단이 ×2 배율뿐 → 스테이지마다 약 2.5배씩 오래 걸림 (7스테이지 ≈1h → 10스테이지 ≈15h, 12 ≈100h 추정).
- 업그레이드 3종이 모두 "개수 증가"라 코인 등급 외에는 화면 변화가 거의 없음.

## 2. 목표 / 비목표 / 반목표

**목표**
- 초기화(prestige)로 "사다리 오르기" 루프를 만든다: 리셋할수록 초반 스테이지가 순식간에 지나가고, 매 판 조금씩 더 멀리 간다.
- 눈에 보이는 성장 이벤트를 촘촘히: 패드 색 진화, 새 코인 등급, 새 패드 슬롯, 피버, CASH OUT 연출.
- 방치(SPEED·배율)와 들여다보기(탭 피버, 구매 결정) 둘 다 재미있게.

**비목표 (이번 범위 아님)**
- 마일스톤 보너스(배율 스파이크), 업적, 2단 prestige, 사운드트랙, 클라우드 세이브.
- 칩 상점의 FEVER+ / OFFLINE+ 같은 추가 항목 — 나중에 필요해지면.

**반목표 (이러면 기술적으로 돌아가도 실패)**
- 기존 세이브가 날아가거나 진행이 깎인다 (사용자가 폰에서 실제 플레이 중).
- 첫 CASH OUT까지 1시간 이상 걸리거나, 리셋 후 첫 판보다 느리게 느껴진다.
- 픽셀 감성/네온 아트 톤이 깨진다 (부드러운 UI, 안티앨리어싱 텍스트, 외부 폰트·에셋 추가).
- 물리 튜닝이 망가져 코인이 끼거나 패드를 통과한다.

## 3. 제약

- 단일 `index.html`, 에셋 0개, 180×320 논리 캔버스 + 3×5 비트맵 폰트. 폰은 `EX`(늘어난 하늘 높이) 고려 필수 — 좌표 하드코딩 시 `EX` 반영.
- 한 줄 함수 안에 `//` 주석 금지 (나머지 줄이 주석화됨).
- 수정 후 `sw.js`의 `VERSION`을 반드시 올린다 (`bb-3` → `bb-4`). cache-first라 안 올리면 폰에 옛 버전이 남음.
- 커밋 작성자는 레포 로컬 noreply 이메일 (이미 설정됨). 공개 레포.
- 물리는 고정 스텝 `STEP=1/120`. 속도 증가는 **스텝 크기가 아니라 스텝 횟수**로 (터널링 방지).

## 4. 검토한 접근

| 결정 | 고른 것 | 대안과 버린 이유 |
|---|---|---|
| prestige 보상 | **배율 + 영구 칩 상점** (사용자 선택) | 순수 배율: 단순하나 리셋 시 화면 변화 적음 / 상점만: "배율 몇 배" 느낌 약함 |
| 패드 성장 | **레벨업(색 진화) + prestige로 슬롯 추가** (사용자 선택) | 레벨업만: 슬롯 확장 재미 없음 / 슬롯만: 외형 변화 없고 바구니 붐빔 |
| 속도 | **돈으로 사는 SPEED 레벨 + 탭 피버(쿨다운)** (사용자 선택) | 업그레이드만: 들여다볼 이유 약함 / 피버만: 방치 중 성장 없음 |
| 속도 상한 | **화면 ×3 상한 + 초과분은 수익 배율** (사용자 선택) | 말 그대로 ×6: 코인이 순간이동처럼 보여 이펙트 감상 불가 / 최대치 하향(×3.9): 단순하나 성장 폭 축소 |
| 하단 UI | **카드 4장 PAD/COIN/MERGE/SPEED** (사용자 선택) | BUILD/BOOST 탭 2개: 글씨는 크지만 절반이 가려져 구매 기회를 놓침 |
| 구현 구조 | **index.html 내부 확장** (Claude 판단) | 파일 분리: "단일 파일·에셋 0" 구조만 깨고 얻는 게 없음 |

## 5. 설계

### 5.1 수익 공식

```
바운스 수익 = TIERS[coin].v × padMult(pad) × 2^(stage-1) × chipMult()
padMult(pad)  = 2^(padLv[pad]-1)
chipMult()    = 1 + CHIP_BONUS × chipsEver      (CHIP_BONUS 초기값 0.1, 시뮬로 조정)
```
- `chipsEver`는 **지금까지 받은 칩 총량** → 상점에서 칩을 써도 배율은 줄지 않는다.
- 하단 정보 줄의 `X… INCOME` 표시는 `2^(stage-1) × chipMult()` 합산값.

### 5.2 패드 레벨 (per-run)

- 패드마다 `padLv` 1~8. 레벨당 바운스 수익 ×2.
- 외형: LV1 = 현재 팔레트 모습(시안 + 노랑 스트라이프). LV2~8 = 코인 등급 색을 재사용 → SILVER, GOLD, EMERALD, RUBY, SAPPHIRE, AMETHYST, PRISM(무지개 애니메이션). `buildPadSprites`가 레벨별 색을 받도록 확장.
- 레벨업 순간: 패드 플래시 + 파티클 + `PAD LV3!` 팝업 + 짧은 shake.
- 모든 패드가 같은 레벨에 도달하면 배너 `ALL PADS GOLD!` (보너스 없음, 연출만).

**PAD 카드 동작**
- 빈 슬롯이 있으면 `ADD PAD` (현재 동작).
- 슬롯이 다 차면 `PAD LV+` — 레벨이 가장 낮은 패드(동률이면 인덱스 작은 것)를 +1.
- 전부 LV8이면 `MAX`.
- 카드 아이콘: 다음에 강화될 패드의 색으로 표시, 서브텍스트 `LV3` 또는 `9/12`.

### 5.3 추가 패드 슬롯 (영구, 칩 상점)

- 기존 9개 뒤에 공중(float) 슬롯 3개 추가 → 최대 12. 칩 상점 `PAD SLOT+`로 하나씩 해금.
- 위치는 빌더 판단: 바구니 안 빈 공간에 두되 기존 패드·투입구 낙하선(x=90)과 겹치지 않게, 코인이 끼지 않는지 실제 실행으로 확인. (후보: 중앙 상단 낙하선 근처, 좌우 중단)
- 해금된 슬롯은 다음 판부터가 아니라 **즉시** 빈 슬롯으로 생겨 `ADD PAD`로 살 수 있다.

### 5.4 SPEED (per-run, 돈)

- 4번째 카드. 레벨 0~10, 레벨당 시간 배율 +10% (최대 ×2).
- 속도 총량 = `(1 + 0.1×speedLv) × (1 + 0.1×shopSpeed) × (피버 중 2 : 1)` (최대 ×6).
- **화면 속도 상한 ×3** (사용자 선택): 물리 시간 배율 `timeScale = min(속도 총량, 3)`, 초과분 `speedIncome = 속도 총량 / timeScale`은 바운스 수익에 곱한다. 성장 가치는 ×6 그대로, 화면은 읽히는 속도로 유지.
- 구현: 프레임 루프에서 `acc += dt × timeScale` 후 기존 `STEP`으로 반복 → 물리 정확도 유지. 루프 상한(현재 40)은 ×3에서도 프레임당 필요한 스텝 수를 넉넉히 넘게.
- `update()` 안에서 코인 움직임에 묶인 것(스폰 큐, still 감지, 합체 애니메이션 등)은 스케일된 시간, 파티클·텍스트·배너·카드 애니메이션은 실시간 `dt` (연출이 빨라지면 산만함).

### 5.5 탭 피버

- 플레이필드(상단 바·하단 패널 제외 영역)를 탭하면, 준비 상태일 때 **피버 10초**: 시간 배율 ×2, 바구니 네온이 무지개로 펄스, `FEVER!` 배너/팝업, 상승 아르페지오 SFX.
- 이미 화면 상한 ×3에 닿아 있으면 피버의 ×2는 수익 쪽(`speedIncome`)으로 넘어간다 — 무지개 연출은 항상 동일.
- 쿨다운 60초 (실시간 기준, 속도 배율 무관). 준비 안 됐을 때 탭하면 작은 팝업 `READY IN 34S`.
- 정보 줄에 피버 아이콘: 준비=깜빡임, 쿨다운=남은 비율 표시.
- 피버 중에는 `ips`(초당 수익 측정) 갱신을 멈춘다 → 피버 중 앱을 닫아도 오프라인 수익이 부풀지 않게.
- 첫 진입 시(피버 미사용 상태) 플레이필드에 `TAP!` 힌트 1회.

### 5.6 CASH OUT (prestige)

- **해금**: 이번 판 `stage ≥ 6` (첫 판 기준 약 25~35분 목표, 시뮬로 확인).
- **칩 계산** (AdVenture Capitalist 방식, 누적 수익의 √):
  ```
  chipsTotal(L) = floor( sqrt(L / CHIP_K) )      L = lifetimeEarned (모든 판 누적)
  gain          = chipsTotal(lifetimeEarned) - chipsEver
  ```
  `CHIP_K`는 첫 판 stage 6 도달 시 gain ≈ 5~10이 되도록 시뮬로 정한다. √라서 같은 지점에서 리셋하면 칩이 점점 덜 나옴 → 매번 더 멀리 가야 함.
- **리셋되는 것**: money, stage→1, stageEarned, 코인(→시작 코인), padCount(→시작 패드), padLv 전부 1, speedLv 0, 피버 쿨다운, 팔레트, `ips`(0으로 — 리셋 직후 오프라인 수익이 부풀지 않게).
- START+로 시작 코인이 stage 1 코인 상한을 넘으면 상한을 시작 코인 수까지 올린다 (Claude 판단).
- **유지되는 것**: chips(보유), chipsEver, 상점 레벨, lifetimeEarned, best(새 코인 배너 중복 방지), muted.
- **연출** (이번 작업의 하이라이트): 확인 → 모든 코인이 투입구로 빨려 들어감 → 화이트 플래시 → 칩 카운터 롤업 → 배너 `CASH OUT! / +12◆ / INCOME X3.2` → 스테이지 1 팔레트로 재시작.
- 확인 단계 필수 (실수 방지): BANK 화면에서 CASH OUT → `RESET? +12◆ [YES] [NO]`.

### 5.7 BANK 화면 (칩 상점 + CASH OUT)

- 하단 정보 줄의 `◆30 X4.0` 영역을 탭하면 오버레이로 열림. 게임은 뒤에서 계속 돈다.
- CASH OUT 가능 + gain ≥ 1이면 `◆` 표시가 깜빡임.
- 구성 (위→아래): 제목 `BANK`, 보유 칩 / 배율, CASH OUT 버튼(`+N◆`, 잠김 시 `REACH STAGE 6`), 상점 항목 4개, 닫기.
- 상점 항목 (비용은 시뮬로 조정, 아래는 시작값):

| 항목 | 효과 | 최대 | 비용 시작값 |
|---|---|---|---|
| SPEED+ | 기본 시간 배율 +10%/레벨 | 5 | 3, 6, 12, 24, 48 |
| PAD SLOT+ | 공중 패드 슬롯 +1 | 3 | 8, 20, 50 |
| NEW TIER | PRISM 다음 코인 등급 해금 | 3 | 20, 60, 180 |
| START+ | 판 시작 시 패드 +1, 코인 +2 | 5 | 2, 5, 10, 20, 40 |

### 5.8 신규 코인 등급 (NEW TIER로 해금)

PRISM 다음 3개. 값은 ×3 비율 유지, 반지름 8~9. 각각 고유 엠블럼(5×5)·팔레트·fx:
- **NOVA** (v 10000) — 흰빛·금빛 초신성. fx: 바운스 시 십자 섬광 + 확장 링.
- **COSMOS** (v 30000) — 짙은 남색 + 별 반짝임. fx: 궤도 별 파티클, 은하 소용돌이.
- **OMEGA** (v 100000) — 검정 몸체 + 무지개 테두리. fx: prism + volt 혼합, 바운스마다 강한 shake.

해금되지 않은 등급으로는 MERGE 불가 (`MAXT`가 해금 수에 따라 동적). 처음 만들면 기존처럼 `NEW COIN!` 배너.

### 5.9 하단 UI — 카드 4장

- 카드 폭 42px × 4 + 간격 2px (좌우 여백 3px). 카드 구조(이름 / 아이콘 / 서브텍스트 / 가격 버튼)는 현재와 동일.
- 가격은 폭에 맞으면 scale 2, 아니면 scale 1 (현재 폴백 로직 재사용).
- 정보 줄: `$/S 1.2K` · `◆30 X4.0`(탭→BANK) · 피버 아이콘 · 음소거.
- 키보드: 1~4 카드, `b` BANK, `f` 피버, `m` 음소거.

### 5.10 세이브

- `KEY` 그대로, `v:2`로 올림. 추가 필드: `padLv[]`, `speedLv`, `chips`, `chipsEver`, `lifetime`, `shop{speed,slot,tier,start}`, `feverCD`.
- 마이그레이션 전에 v1 원본을 별도 키(`bounceBank.v1.bak`)에 백업 — 폰에 캐시된 옛 코드가 v2 세이브를 "없음"으로 읽고 새 v1 세이브로 덮어쓰는 사고 대비 (Claude 판단).
- **v1 → v2 마이그레이션**: 진행 그대로 유지, `padLv` 전부 1, 나머지 0. `lifetime`은 `sum(goal(1..stage-1)) + stageEarned`로 추정 → 기존 플레이어도 첫 CASH OUT 칩을 정당하게 받음.
- `#reset` 동작 유지.

### 5.11 밸런스 목표 (node 경제 시뮬로 튜닝)

| 구간 | 목표 |
|---|---|
| 1판 stage 1 | ≈2분 (현재 유지) |
| 1판 stage 6 (CASH OUT 해금) | 25~35분 |
| 2판 | 1판 stage 6 지점을 10분 안에 통과, stage 7~8 도달 |
| 이후 판 | 판당 30~60분에 이전 최고 +1~2 스테이지 |
| 눈에 띄는 이벤트 간격 | 초반 2~5분, 후반에도 15분 이상 비지 않게 |

튜닝 대상: `padCost`, 레벨업 비용, SPEED 비용, `CHIP_K`, `CHIP_BONUS`, 상점 비용. 기존 `goal()`·`coinCost`·`mergeCost`는 가능하면 유지.

시뮬 가정 (Claude 판단): 가장 싼 효율 구매를 하는 greedy 플레이어, 피버 미사용. 피버는 최대 ~17% 가속이라 실제 플레이는 목표보다 빠르기만 하다.
